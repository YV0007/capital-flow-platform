# Экосистема — вторая карта в секции Capital Flow

**v4** — архитектура движка + компании, живущие в нескольких слоях, решены без дублирования.
Стиль, канвас, планеты, зум — без изменений. Меняется только содержание.

---

## 0. Зачем вторая карта

> Сначала понять, как устроена отрасль. Потом смотреть, куда в ней идут деньги.

| | Потоки (v1, работает) | Экосистема (v2) |
|---|---|---|
| Отвечает на | Куда пошли деньги на неделе | Как отрасль устроена и кто её держит |
| Узел | Аллокатор / получатель | **Компания** в слое стека |
| Ребро | Сделка: сумма, дата | Зависимость: поставка, контракт, владение |
| Природа | **Событие с датой** | **Стоящая позиция**, без даты |
| Размер узла | Капитал | **Критичность** — насколько незаменим |
| Обновление | Еженедельно | **Ежемесячно** |

Две раздельные карты: свои фильтры, своя панель, никакой взаимной подсветки.
Общая только оболочка — тема канваса, лого, форматтеры.

## 1. Модель

### 1.1 Узел — компания, а не слой

```
SK Hynix ──▶ NVIDIA ──▶ Foxconn ──▶ CoreWeave ──▶ OpenAI       ✅
ПАМЯТЬ  ──▶ ЧИПЫ  ──▶ СБОРКА ──▶ ВЫЧИСЛЕНИЯ ──▶ РЕЗУЛЬТАТ      ❌
```

- Кликабельный объект один — **компания**.
- **Слой `L1…L12`** — координата: задаёт радиус, подписан на краю кольца. Отчёт по слою
  открывается с подписи, не с узла.
- Узел может занимать **несколько слоёв** — Broadcom, Samsung, Alphabet. Тогда он один,
  но растянут через них (§3.4). Дублей нет.
- **Сектор** (44 из DC-AI) — атрибут для упаковки и фильтра, не объект.
- Таксономия слоёв и секторов берётся готовой из `Roadmap.jsx`.

### 1.2 Роль узла — второе измерение

| Роль | Кто |
|---|---|
| `producer` | Производитель — то, что покрыто в DC-AI |
| `owner` | Собственник / оператор актива — Equinix, Digital Realty, Constellation |
| `capital` | Капитал, **создающий** активы — Brookfield, Blackstone, KKR, MGX, Stonepeak |
| `demand` | Конечный спрос — гиперскейлеры, лаборатории |
| `platform` | Тех-узел — CUDA, EUV, CoWoS, HBM |

### 1.3 Рёбра — десять типов, два хребта

| Тип | Хребет | Значение | Пример |
|---|---|---|---|
| `supply` — поставляет | физ. | Критический физический вход | SK Hynix → NVIDIA (HBM) |
| `offtake` — контракт | физ. | Выкуп мощности, sole-source | OpenAI → Oracle |
| `platform` — встроен | физ. | IP / софт / стандарт внутри чужого продукта | Arm → все SoC |
| `partner` — строит вместе | физ. | СП, co-design | NVIDIA ↔ Foxconn |
| `compete` — замещает | физ. | Второй источник, угроза | Broadcom ASIC → NVIDIA GPU |
| `owns` — владеет | кап. | Контроль через собственность | Brookfield → Westinghouse |
| `stake` — доля | кап. | Пакет без контроля | NVIDIA → OpenAI, xAI |
| `finances` — финансирует | кап. | Проектное финансирование, JV | Brookfield ↔ фабрика Intel |
| `develops` — создаёт актив | кап. | Девелопмент объекта | Brookfield → Compass, Data4 |
| `operates` — эксплуатирует | кап. | Управление активом | оператор ДЦ |

Направление всегда снизу вверх по стеку (поставщик → потребитель).
Ребро несёт: `type`, `strength` 0–100 (существенность **для получателя**), `source`, `date`,
`evidence` (цитата), `tier`.

> `compete` определён, но **в v1 не собирается** — это суждение, а не факт из релиза.

### 1.4 Тех-узлы

~12 штук: EUV, CUDA, HBM, CoWoS, InfiniBand, PyTorch, Arm ISA. У каждого есть
владелец-компания; рисуются спутником рядом с ней, в цепочке — подписью на ребре.
CUDA объясняет власть NVIDIA лучше, чем сама NVIDIA.

## 2. Хребет капитала: одних производителей мало

DC-AI покрывает физическую цепочку. Brookfield в ней не стоит — он на параллельном хребте
и дотягивается внутрь через владение.

```
Brookfield + Cameco ──владеют──▶ Westinghouse ──▶ реакторы AP1000 ──энергия──▶ ДЦ ──▶ модели
```

Не поставщик и не покупатель — **собственник узкого места**. На карте из одних
производителей эта связь невидима, хотя определяет, кто держит ядерное плечо ИИ.

**Механизм «актив как способ финансирования»:**

```
строит актив → долгосрочный контракт → контракт делает актив финансируемым
      ▲                                              │
      └────────── под это привлекается капитал ◀─────┘
```

Замкнутый контур — то, что ловит линза «круги» (§4.3). У Brookfield контур финансирования,
у NVIDIA контур сбыта (доля в лаборатории → она покупает GPU → выручка → новая доля).
Один приём, два мотора отрасли. Это и есть ответ, зачем нужна вторая карта.

**Кандидаты (~15–20):** Brookfield (+ Westinghouse, Renewable, Compass, Data4), Blackstone
(+ QTS), KKR, MGX, Stonepeak, GIP/BlackRock, Ontario Teachers', Digital Realty, Equinix,
Vantage, Constellation, Vistra, Crusoe, CoreWeave, Oracle.

## 3. Геометрия и взаимодействие

### 3.1 Кольца стека
Центр — дефицитные слои (материалы, оборудование), наружу — к спросу. Кольцо = слой,
12 слоёв в 5 цветовых полосах. Внутри кольца — упаковка по секторам, сортировка по
критичности. Та же геометрия, что на карте потоков, только колец больше.

### 3.2 Режим «Цепочка» — главное взаимодействие
Клик по компании → карта гаснет, загорается её путь по стеку: вверх — от кого зависит,
вниз — куда уходит результат.

```
центр (сырьё) ──────────────────────────────────────────▶ край (спрос)
ASML ──▶ TSMC ──▶ NVIDIA ──▶ Foxconn ──▶ CoreWeave ──▶ OpenAI
```

Слой = радиус, поэтому цепочка рисуется **лучом из центра наружу** — линия через всю карту,
а не клубок. Это аргумент за кольца против «солнц».

| Контрол | Что делает |
|---|---|
| Глубина | 1 шаг · 2 шага · вся цепочка |
| Направление | вверх · вниз · обе |
| Тип связи | `supply` — физическая цепочка · `owns`/`finances` — цепочка контроля · всё |

**Ветвление:** на каждом шаге топ-N ветвей по `strength`, остальные в «ещё N» — иначе
загорится вся карта. Тот же механизм для капитала:
`Brookfield —владеет→ Westinghouse —поставляет→ AP1000 —энергия→ ДЦ`.

### 3.3 Цепочка текстом
Под картой — кликабельные хлебные крошки с типом связи на стрелке:

> **ASML** —поставляет→ **TSMC** —производит→ **NVIDIA** —co-design→ **Foxconn** —→ **CoreWeave**

Это можно прочитать вслух и пересказать.

### 3.4 Компании в нескольких слоях — один узел, растянутый

Alphabet — это TPU (L3), облако (L10) и модели (L12). Broadcom — чипы и сетевой кремний.
Samsung — память и фаундри. Дублировать узел нельзя: два «Alphabet» на карте — это две
разные компании для глаза.

**Решение: узел рисуется не кругом, а радиальной капсулой** от своего нижнего слоя до
верхнего.

```
   центр ─────────────────────────────────────────────▶ край
   L3          L10        L12
   ▓▓▓▓▓▓▓▓░░░░░▓▓▓▓▓▓▓░░░░▓▓▓▓▓▓        ← Alphabet: один узел, три утолщения
   TPU        облако     модели
```

- Толщина капсулы в каждом слое = критичность **именно в этом слое**.
- Подпись и лого — в основном слое (где критичность максимальна).
- В промежуточных слоях, где компания не работает, капсула тоньше — это перемычка, не присутствие.
- **Цепочка (§3.2) цепляется к нужному сегменту:** маршрут через облако входит в Alphabet
  на L10 и выходит на L12, а не в центр узла. Это и есть «связать слои через сам узел».

**Побочный выигрыш:** вертикальная интеграция становится **формой**, а не сноской. Длинная
капсула от кремния до моделей — это буквально картинка «пытается владеть всем стеком»:
Alphabet, Amazon (Trainium → AWS → модели), Microsoft, Samsung. Один взгляд на карту
отвечает, кто строит вертикаль, а кто сидит в одном звене.

## 4. Четыре линзы

### 4.1 Критичность (0–100) → размер узла
Четыре фактора, дискретный выбор 0–5, не «на глаз». Пересчитывается скриптом.

| Фактор | Вес | 5 | 3 | 1 |
|---|---|---|---|---|
| Доля в своей функции | 0.30 | > 90% | 50–70% | < 30% |
| Реальных альтернатив | 0.30 | нет | две | много |
| Время замены | 0.25 | > 5 лет | 1–3 года | < 6 мес. |
| Порог входа | 0.15 | запретительный | высокий | низкий |

`score = 100 × Σ(вес × фактор) / 5` → ASML **100**, ODM-сборщик **26**.
Четыре входа хранятся в узле: панель показывает не «98», а *почему* 98.

### 4.2 Гравитация
Сколько узлов задето, через сколько слоёв, сколькими типами связей. Намеренно расходится с
критичностью: Microsoft — высокая гравитация, низкая критичность; ASML наоборот. Обе в
панели, не смешиваются.

### 4.3 Круги
Детект циклов: NVIDIA → доля в OpenAI → OpenAI покупает у CoreWeave → CoreWeave покупает
GPU у NVIDIA. Единственная линза без оценок — цикл есть свойство графа. Самая дешёвая и,
вероятно, самая сильная на экране. Стыкуется с `proxy-circular.json`.

### 4.4 Концентрация слоя → цвет кольца
Монополия / олигополия / конкурентный. Кольцо, где один держит 90%, выглядит тревожно на
карте, а не в сноске.

## 5. Объём v1

**Одна экосистема — ИИ / ДЦ** (285 компаний, 44 сектора, 12 слоёв уже готовы).
**~150 узлов.** Узел проходит, если выполнено хотя бы одно:

- **R1** топ-3 по доле в своей функции;
- **R2** единственный / почти единственный поставщик критического входа (критичность ≥ 70);
- **R3** названный контрагент в контракте или партнёрстве с якорем;
- **R4** восходящий с **подписанным** контрактом или design win (не «перспективная идея»);
- **R5** контролирует узкое место **через собственность или финансирование**.

**Якоря (~10):** NVIDIA, TSMC, ASML, Broadcom, Microsoft, Alphabet, Amazon, OpenAI,
SK Hynix, Foxconn. Кандидаты: Oracle, Brookfield, Anthropic.
**Восходящие:** Astera Labs, Credo, Celestial AI, Crusoe, Nebius, Lambda, Oklo, Alchip.

## 6. Панель узла и отчёт по слою

**Узел:** роль одной строкой · критичность с разбивкой по 4 факторам · гравитация ·
вверх по стеку топ-5 · вниз топ-5 · доля функции и концентрация · публичная/частная,
тикер, как получить экспозицию (из `dc-companies.json`) · что сломает позицию ·
источник по каждому ребру · ссылка в тезис DC-AI.

**Слой** (с подписи кольца): кто контролирует, концентрация, узкое место, есть ли второй
источник, что изменилось за месяц.

## 7. Архитектура

### 7.1 Где это живёт

**Тот же движок, что у Capital Flow — отдельный конвейер внутри него.**

```
~/Desktop/Capital Flow/          ← движок (агенты + Python + SQLite)
        │
        ├── еженедельный конвейер → handoff/capital_map.json   → карта потоков
        └── ЕЖЕМЕСЯЧНЫЙ конвейер  → handoff/ecosystem_map.json → карта экосистемы
                                                    │
                                       ab-investment/src/data/  ← дашборд, чистый потребитель
```

Не отдельный репозиторий — потому что **идентичность сущностей общая**. У движка уже есть
`entity_aliases`, `entity_external_ids`, `config/aliases.yaml`: там NVIDIA — одна NVIDIA.
Второй репозиторий немедленно разъедется с первым в названиях. Общими остаются:
резолвинг сущностей, реестр источников `config/sources.yaml`, инфраструктура прогонов,
паттерн handoff. Раздельными: таблицы, агенты, правила, расписание.

На дашборде это по-прежнему **две несвязанные карты** — общий только бэкенд.

### 7.2 База данных

SQLite, тот же `db/capital.db`, новые таблицы с префиксом `eco_`:

```sql
eco_nodes      id, name, sector, role, is_anchor, is_emerging,
               ticker, public_private, one_liner,
               f_share, f_alternatives, f_switch_time, f_barrier,   -- 0..5, входы рубрики
               criticality,                                          -- считается из четырёх
               first_seen, last_confirmed, stale

eco_node_layers node_id, layer(L1..L12), is_primary, criticality_in_layer
               -- компания в нескольких слоях = несколько строк, а не второй узел.
               -- Отсюда рисуется капсула (§3.4) и к нужному слою цепляется цепочка.

eco_edges      id, source_id, target_id, edge_type(10 значений), strength 0..100,
               started, ended, last_confirmed, status(active|expired|unverified)

eco_evidence   edge_id, source_url, source_tier, quote, published_date, fetched_date, alive
               -- много строк на ребро: правило двух источников считается отсюда

eco_scores     node_id, run_id, criticality, gravity, layer_concentration
eco_cycles     run_id, path(JSON), cycle_type(sales|financing), members
eco_runs       id, month, agent, rows_in, rows_rejected, notes
```

Ключевое: **`eco_evidence` отдельной таблицей**, а не колонкой в ребре. Отсюда бесплатно
берутся правило двух источников, тир уверенности и месячная перепроверка живости ссылок.

### 7.3 Агенты — что именно ищут

Шесть месячных агентов (брифы `agents/eco-*.md`, формат как у существующих), нарезка по
слоям, а не по классам аллокаторов:

| Агент | Слои | За чем идёт |
|---|---|---|
| `eco-silicon` | L1–L4 | материалы, оборудование, фаундри, чипы, HBM |
| `eco-systems` | L5, L8–L9 | упаковка, платы, сети, оптика, серверы, охлаждение |
| `eco-power` | L6–L7 | генерация, турбины, трансформаторы, атом, SMR |
| `eco-infra` | L10 | ДЦ, REIT, неклауды, гиперскейлеры |
| `eco-models` | L11–L12 | лаборатории, софт, оркестрация, спрос |
| `eco-capital` | сквозной | `owner` / `capital`: владение, JV, проектное финансирование |

**Что агент выдаёт — два CSV, как сейчас:**

- `edges.csv` — `source, target, edge_type, strength, evidence_quote, source_url,
  source_tier, published_date`
- `nodes.csv` — `name, layer, sector, role, f_share, f_alternatives, f_switch_time,
  f_barrier, share_note, one_liner, ticker`

**Что ищем конкретно:** в 10-K/20-F — разделы про концентрацию поставщиков и клиентов
(«customer A accounted for X% of revenue»); в 8-K и проспектах — сделки владения и JV;
в пресс-релизах — контракты, co-design, объёмы; в звонках — подтверждение зависимостей
своими словами; у TrendForce / Omdia — доли рынка (только как `estimate`).

**Правило:** нет дословной цитаты — ребро не пишется. Это отсекает выдуманные связи,
которые звучат правдоподобно.

### 7.4 Достоверность — механическая, без ручной сверки

| Защита | Как работает |
|---|---|
| Нет источника — нет ребра | Схема требует `evidence` + `source_url`; иначе строка отклоняется на ingest |
| Тир источника виден на карте | `filing` / `company_pr` / `transcript` → сплошная; `press` / `estimate` → пунктир с подписью |
| Автопроверка ссылок | Ежемесячно: жива ли страница, есть ли на ней цитата. Нет → `unverified`, ребро гаснет |
| Перекрёстная сверка движком | `stake` / `owns` / `finances` уже доказываются недельным конвейером → метка «подтверждено движком» |
| Правило двух источников | Сплошная линия только при ≥ 2 независимых строках в `eco_evidence` |
| Устаревание | Старше 6 месяцев без подтверждения — блёкнет, «не подтверждалось с …» |

Карта показывает собственный распад вместо того, чтобы молча врать.

### 7.5 Месячный конвейер

```
run_month.py:
  6 агентов → runs/<месяц>/eco-*/ (CSV)
    → eco_ingest.py    валидация, резолвинг имён, дедуп, загрузка
    → eco_verify.py    перепроверка ссылок и цитат, устаревание
    → eco_score.py     критичность из 4 факторов, гравитация, концентрация слоёв
    → eco_cycles.py    детект замкнутых контуров
    → eco_handoff.py   → handoff/ecosystem_map.json + ECOSYSTEM-CHANGELOG.md
```

Агенты — недетерминированный слой, всё остальное — детерминированный Python + SQL.
Ровно та же философия, что у недельного конвейера.

### 7.6 Контракт передачи и роль человека

- `handoff/ecosystem_map.json` — состояние карты: узлы, рёбра, оценки, циклы.
- `ECOSYSTEM-CHANGELOG.md` — **диф на 10–20 строк**: что появилось, что отвалилось, где
  сменился владелец, где ребро погасло.

Дашборд остаётся чистым потребителем: положить новый файл в `src/data/` → карта меняется
без правок кода, как сейчас с `capitalMap.json`.

**Твоё единственное действие — прочитать диф.** Это чтение списка изменений, а не сверка
данных.

| `compete` | Не в v1 |
| Кольца | Материалы в центре → спрос наружу; 12 слоёв в 5 полосах |
| Взаимодействие | Режим «Цепочка» + хлебные крошки |
| Компании в нескольких слоях | Один узел — радиальная капсула через слои; дублей нет |
| Порог `strength` | В БД пишется всё; на карту по умолчанию от **20**, ползунком до 0; в панели узла — всегда полный список |
| Достоверность | Механическая (§7.4), без ручной сверки |
| Где движок | Тот же репозиторий Capital Flow, отдельный месячный конвейер |
| База | SQLite `capital.db`, таблицы `eco_*`, доказательства отдельной таблицей |
| Обновление | Ежемесячно, 6 агентов, диф на 10–20 строк |

## 10. Отложено — не в v1

- **Слой `compete`** (замещение) — суждение, а не факт из релиза; отдельным слоем после Ф5.
- **Метка «в портфеле»** — Brookfield, KKR, TPG, Constellation уже в `holdings-v2`.
  Пересечение хребта капитала с личным портфелем; вернуться после v1.
- **Другие экосистемы** — оборона, энергетика. Та же схема, новые агенты, без переделки.
