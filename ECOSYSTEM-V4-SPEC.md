## 1. Диагноз. Почему это делается

Карта заявляет себя как «сеть ИИ-инфраструктуры из 27 равноправных пивотов». Проверка
доставленного `handoff/ai_ecosystem_network.json` показывает другое:

| факт | значение |
|---|---|
| сущностей, у которых **ВСЕ** источники — URL, принадлежащие NVIDIA | **41 из 107** |
| медиана числа источников на профиль сущности | **1** |
| источников профилей с sec.gov | 170, из них **58 — отчётность CIK 1045810 (NVIDIA)** |
| тиры источников профилей | только 1, 2 и 4 — шкала «близость к NVIDIA» |
| степень NVIDIA / средняя степень по сети | 74 / 3.79 |

**Уточнение по итогам Фазы 0 (читать вместе с таблицей выше).** Пересчёт на месте дал
картину хуже исходной оценки, и меряться надо от неё:

| величина | значение |
|---|---|
| сущностей **без единой собственной цитаты** | **75 из 107** — это долг кампании |
| профилей, у которых источников **ровно один** | **107 из 107** |
| сущностей, прошедших бы все три проверки членства | **0 из 107** |
| разрыв `integration` между 1-м и 2-м местом | **семикратный** (NVIDIA 100 / TSMC 30) |

41 — это сущности, чей единственный издатель NVIDIA. 75 — сущности, у которых нет
СВОЕГО голоса вообще (сюда добавляются описанные отчётностью Amazon, статьёй
TrendForce и т.п.). Закрывать надо второе число. «Карта из 107 сущностей» — это на
сегодня карта из 41 исследованной сущности и 67 упоминаний.

38% узлов карты **никогда не исследовались как самостоятельные сущности**. Их профиль —
это то, что о них говорит отчётность NVIDIA. Профиль Arista — это раздел про сети в
10-K NVIDIA. Это не карта экосистемы, это аннотированная библиография документов одной
компании.

**Корневая причина — понятие «якорь» выполняет ТРИ разные работы сразу:**

1. **Членство** — кто вообще на карте (правило двух шагов от NVIDIA).
2. **Доказательство** — чьё слово чего стоит (тир 1 = говорит NVIDIA).
3. **Важность** — насколько узел велик (`strategicControl` = рычаг NVIDIA над ним).

Пока эти три работы слиты в одно понятие, убрать якорь = убрать карту. **Задача этого
прогона — развести их на три независимых, безъякорных механизма.** Ни одному из трёх
центр не нужен.

**Хорошая новость: якорь заражает шесть мест, а не весь движок.**

| уже безъякорное — НЕ ТРОГАТЬ | заражено якорем — переделать |
|---|---|
| 16 слоёв, 38 секторов | `config/nveco_anchors.yaml` (правило шагов) |
| 33 типа связей, 5 хребтов | `nveco_domain_tiers` (зашитые nvidia.com, CIK 1045810) |
| `lockInDepth`, `timeToReplace` | названия `nveco_tiers` («Официальная NVIDIA») |
| gravity, циклы, центральность, SPOF | фактор `strategicControl` (вес 0.15) |
| правило «нет цитаты — нет связи» | формулировка `irreplaceability` («может ли NVIDIA заменить») |
| валидаторы, ретирование, i18n, весь Python | брифы агентов + `nveco_watchlist.yaml` |

Два из четырёх факторов рубрики **уже** относительны экосистеме, а не якорю. Одному
нужна другая формулировка вопроса. Выбросить надо ровно один.

## 2. Что уже решено. Не переоткрывай

Пользователь выбрал три развилки. Это вход, а не предмет обсуждения:

1. **Миграция — поэтапная, семя сохраняется.** Существующие 107 сущностей и 262 связи
   не выбрасываются. Фаза 0 расснимает якорь на уже собранных данных, досье заменяют
   NVIDIA-источники волнами. Карта живёт и улучшается всё время миграции.
2. **Покрытие — ярусная ротация.** Ядро (~30 по интеграции) — полное досье ежемесячно;
   средний ярус — ежеквартально; хвост — по триггеру (новая связь коснулась узла) или
   по 6-месячной устарелости. ≈40 досье в месяц.
3. **Ядро выводится из данных ежемесячно.** «Ядро» = верхние N по вычисленной
   интеграции, пересчёт каждый прогон. Список руками не ведётся. Повышения и понижения
   идут в чейнджлог.

4. **Полная автономия на всю кампанию.** Пользователь не подтверждает промежуточные
   решения — ни разу, ни в одной фазе. Развилка решается на месте и записывается в
   журнал сборки с обоснованием. Это относится и к правкам контракта (§4): если по ходу
   выяснится, что форма файла должна быть другой — **меняй и записывай**, не
   останавливайся. Кампанию ведёт оркестратор, он читает журналы между сессиями и
   переносит изменившийся контракт в промпт дашборда. Единственные настоящие стопы:
   валидатор не проходит, или правка ломает недельный конвейер / Fund Tracker.

# 5. ЧЕТЫРЕ ПРАВКИ

## Правка 1 — Членство: охват и плотность вместо расстояния

**Удали `config/nveco_anchors.yaml`.** Создай `config/nveco_scope.yaml`:

**Гейт по покрытию (правка по итогам Фазы 0).** `min_sources` и `min_self_sources`
применяются к сущности **только после того, как её досье отработано**. Непокрытая
сущность несёт `pendingDossier: true`, показывается, помечена и не ретируется. Иначе
включение членства ретирует большинство карты за то, что до неё не дошла очередь
ротации — наказание за отсутствие исследования вместо отсутствия оснований.
`in_scope` и `min_confirmed_edges` действуют на всех сразу.

```yaml
# Экосистема определяется СВОИМ предметом, а не компанией в центре.
scope:
  ru: "Инфраструктура ИИ: всё, без чего современная модель не может быть обучена,
       развёрнута, запитана, произведена или разрешена к продаже."
  en: "AI infrastructure: everything without which a modern model cannot be trained,
       served, powered, manufactured or legally sold."
  layers: [L0, L1, …, L15]   # предмет = 16 слоёв, они и есть граница

membership:                   # три проверки, все обязательны
  in_scope: true              # 1. работает хотя бы в одном слое охвата
  min_sources: 3              # 2. собственное досье: ≥3 источника
  min_self_sources: 1         #    из них ≥1 опубликован ею самой (см. Правку 2)
  min_confirmed_edges: 2      # 3. ≥2 подтверждённые связи с сущностями на карте

core:
  rule: top_n_by_integration
  n: 30
```

Правило двух шагов из `nveco_ingest` **вырезается целиком** вместе с полем `hops`.
Вместо него — три проверки выше. Отклонение по-прежнему пишется в
`runs/<месяц>/_rejected/` **с причиной**, никогда молча.

Сущность, которая не проходит проверку 2 или 3, но названа в чужом досье, попадает в
**очередь кандидатов** (`runs/<месяц>/_queue/candidates.csv`) и берётся в работу
следующим циклом. Так на карту заходит `Carl Zeiss SMT`: у него есть подтверждённые
связи с ASML и фабами и собственные публикации — трёх проверок ему хватает, а старому
правилу двух шагов от NVIDIA не хватало.

**Ядро — это выход, а не вход.** `core: true` ставит `nvnet_centrality` по верхним 30
`integration.score`. Никакого списка руками. Изменения состава ядра — отдельная
категория чейнджлога.

## Правка 2 — Источники: тир относительно ПРЕДМЕТА, а не NVIDIA

Это главная правка. Лестница остаётся шестиступенчатой, меняется точка отсчёта.

| тир | было | стало |
|---|---|---|
| 1 | официальная NVIDIA | **официальное от САМОГО ПРЕДМЕТА** утверждения |
| 2 | официальное от контрагента о NVIDIA | **официальное от ВТОРОГО КОНЦА** связи |
| 3 | прямая речь принципалов | без изменений |
| 4 | исследования и данные | без изменений |
| 5 | вторичная пресса | без изменений |
| 6 | третичное и сигналы | без изменений |

**Реализация:**

1. Новый реестр `config/entity_domains.yaml`: `id → {domains: [], cik: "…"}`. В payload
   поле `domain` уже есть, но заполнено у 14 из 107 — заполни у всех, кто имеет сайт
   (у технологий вроде `cuda` и юрисдикций вроде `taiwan` доменом считается сайт
   владельца/правительства; если своего издателя нет — поле пустое, и правило
   `min_self_sources` для такой сущности снимается ровно этим фактом, а не исключением
   в коде).
2. `nveco.domain_tier(url)` → **`nveco.source_tier(url, subject_id, counterparty_id=None)`**.
   Логика:
   - домен или CIK принадлежит `subject_id` → **тир 1 (SELF)**
   - домен или CIK принадлежит `counterparty_id` → **тир 2 (COUNTERPARTY)**
   - домен принадлежит любой ДРУГОЙ сущности на карте → тир 2
   - дальше — общая таблица по типу издателя (принципал / данные / пресса / третичное)
3. **Из `config/sources.yaml` удаляются все строки, зашитые под NVIDIA**
   (`nvidia.com`, `edgar/data/1045810`, `blogs.nvidia.com`, …). Они становятся обычными
   данными узла `nvidia` в `entity_domains.yaml`, ничем не отличаясь от строк любого
   другого узла. Блок `nveco_tiers` переписывается в безъякорных формулировках. Блок
   `tier1..tier5` недельного конвейера **не трогается**.

**Два новых правила, которые прямо убивают проблему 41 узла:**

- **`min_self_sources: 1`** — профиль сущности без хотя бы одного источника, изданного
  ею самой, **не проходит ingest**. Компания, описанная только чужой отчётностью, не
  едет на карту. Применяется поэтапно (см. фазы), а не одномоментно.
- **Новый статус доказательства `bilateral`** — оба конца связи утверждают её в
  СОБСТВЕННЫХ документах. Строго сильнее нынешнего «два источника тира 1–2».
  Пересчитай лестницу статусов:

| доказательство | статус |
|---|---|
| SELF-цитата с обоих концов | **`bilateral`** (новый максимум) |
| 2 источника тира 1–2, либо 1×тир 1 + 1×тир 3 | `confirmed` |
| 1×тир 1, либо 2 источника тира 2–3 | `high_confidence` |
| остальное | `signal` |
| один конец утверждает, второй **опровергает** | **`disputed`** — везётся с ОБЕИМИ цитатами |

`disputed` не выбрасывается и не «решается» движком. Расхождение двух компаний в
описании собственных отношений — это находка, а не ошибка данных.

## Правка 3 — Важность: две меры вместо одной

### `criticality` — авторская, из собственного досье узла

```
0.30 · irreplaceability   ← ПЕРЕФОРМУЛИРОВАТЬ: «может ли ЭКОСИСТЕМА обойтись без неё»,
                             а не «может ли NVIDIA её заменить». Шкала та же.
0.30 · lockInDepth        ← без изменений, уже относительна стеку
0.25 · timeToReplace      ← без изменений, уже нейтральна
0.15 · concentration      ← НОВОЕ, вместо strategicControl
```

**`concentration`** — какую долю СВОЕЙ ФУНКЦИИ узел держит. ASML ≈100% EUV. TSMC ≈90%
передового кремния. Шкала: `95–100` монополия (>90% функции) · `85–94` дуополия с
явным лидерством · `75–84` три-четыре игрока, лидер >50% · `65–74` олигополия без
доминирующего · `50–64` конкурентный рынок с барьером входа · `30–49` фрагментированный
· `0–29` коммодити. **Число обязано опираться на цитату** — доля рынка без источника не
едет, как и любая другая цифра.

Веса остаются заморожены контрактом.

### `integration` — вычисленная, из графа. ОСНОВНОЙ РАНГ КАРТЫ

Движок уже считает все составляющие (`gravity` + `centrality`). Собери их в одно
число 0–100:

```
integration = 0.30·degree_n + 0.25·betweenness_n + 0.15·pagerank_n
            + 0.15·layersSpanned_n + 0.10·edgeTypes_n + 0.05·cycles_n
```

(`_n` — нормировка по максимуму в текущем графе.) Веса вынести в
`config/nvnet_edges.yaml` рядом с картой PageRank, чтобы правились без правки кода.
`gravity` сохраняется как есть — не ломай существующее поле, `integration` встаёт рядом.

**Две ортогональные оси.** Интересны узлы, где они расходятся: высокая критичность при
низкой интеграции — скрытая точка удушения (ASML, Zeiss); низкая критичность при высокой
интеграции — хаб (Hugging Face). Точки отказа = верхний правый угол, доказанные
удалением, метод не меняется.

## Правка 4 — Исследование: досье на узел, связь с двух сторон

Единица исследования перестаёт быть «обходом слоя» и становится **одним узлом,
сделанным как следует**. Все узлы получают одинаковое обращение — первого и второго
класса нет.

**Новый бриф `agents/eco-dossier.md`.** Строится по образцу уже работающего
`agents/target-profiler.md` (пакетный профайлер недельного конвейера): на вход — пакетный
файл, на выход — по объекту на сущность. Пакеты собирает новый
`tools/make_dossier_batches.py` по образцу `tools/make_research_batches.py`, включая
контекстный пакет («что уже знаем», «что сработало», «что отклонили в прошлый раз»).

Досье отвечает **из СОБСТВЕННЫХ источников узла**:

```
что это и как зарабатывает            → description (4–7 предложений, {ru,en})
от кого зависит (вверх по стеку)      → рёбра + дословная цитата на каждое
кто зависит от неё (вниз)             → рёбра + дословная цитата на каждое
кто мог бы заменить и за сколько лет  → irreplaceability + timeToReplace + обоснования
какую долю своей функции держит       → concentration + обоснование с цитатой
что она называет, чего нет на карте   → строки в очередь кандидатов
```

**Сверка двух сторон — новое сердце конвейера.** Каждая связь теперь заявляется с обоих
концов двумя независимыми досье. Новая стадия `engine/nveco_reconcile.py` между
`nveco_ingest` и `nveco_score`:

```
A заявил, B подтвердил своими документами  → sidedness: bilateral
A заявил, B молчит                          → sidedness: single    (везётся, помечено)
A заявил, B противоречит                    → sidedness: disputed  (везётся, обе цитаты)
```

Сверка **никогда не решает спор сама** и никогда не удаляет сторону.

**Ротация (решение 2).** Ярус хранится в БД, считается от `integration`:

```
ядро (топ-30 по integration)  → полное досье каждый месяц
средний ярус                   → полное досье раз в квартал
хвост                          → по триггеру: новая связь коснулась узла,
                                 либо 6 месяцев без подтверждения
≈40 досье в месяц, пакетами по 8 → 5 пакетных прогонов + 1 проход сверки
```

**Восемь слоевых агентов (`agents/nveco-*.md`) сохраняются**, но их мандат сужается до
того, чего досье по узлу дать не может: поиск сущностей, которых на карте ещё нет, в
своём слое. `nveco-strategic` переименовывается по смыслу в проход сверки: читает
результат `nveco_reconcile`, разбирает `disputed`, ищет межслойные связи, которых не
заявил ни один конец. Новых сущностей по-прежнему не заводит.

# 6. ФАЗЫ — КТО ИХ ДЕЛАЕТ

Кампания разбита на сессии, потому что одна сессия не удержит и рефакторинг движка, и
сорок исследовательских досье. Каждая — свой промпт, свой коммит, свой раздел журнала.

| промпт | фаза | где | чем занимается | зависит от |
|---|---|---|---|---|
| `ECOSYSTEM-V4-A-ENGINE-DEANCHOR.md` | 0 | движок | конфиги, реестр доменов, функция тира, `concentration`, `integration`, снятие `hops`. Ни одного обращения к интернету | — |
| `ECOSYSTEM-V4-B-ENGINE-DOSSIERS.md` | 1 | движок | бриф досье, пакетчик, стадия сверки, досье на ядро (~30) | A |
| `ECOSYSTEM-V4-C-ENGINE-ROTATION.md` | 2–3 | движок | ротация ярусов, очередь кандидатов, включение членства, ретирование, рабочий регламент | B |
| `ECOSYSTEM-V4-D-DASHBOARD.md` | — | дашборд | адаптер и компоненты под контракт `/4` | A (пишется по факту уехавшего payload) |

Критерии приёмки каждой фазы — в её собственном промпте. Здесь их нет намеренно: фаза
принимается против того промпта, по которому делалась.

# 7. Что остаётся неприкосновенным

- **Нет цитаты — нет связи.** ≤15 слов, дословно, не собрано из кусков, не переведено.
- **Каждая цифра в прозе — из цитаты, привязанной к этой сущности или связи.** Правило
  уже действует для `description` и `edges[].detail`; распространи его на
  `concentration`.
- **Двуязычие.** Каждое прозаическое поле — `{ru, en}`, обе стороны непусты или файл не
  пишется. Цитаты источников не переводятся никогда.
- **Ретирование по `owner_agent`.** Отсутствующий файл = агент не работал (ничего не
  ретируется). Пустой файл = агент ничего не утверждает (строки уходят). Файл, где ВСЕ
  строки отклонены = сбой выгрузки, ретирует ничего, попадает в предупреждения.
- **Агенты дают факты, движок ставит числа.** Ни `integration`, ни `core`, ни `sidedness`,
  ни тир источника агент назначить не может.
- **Детерминированность.** Те же CSV → та же карта. Никаких `Date.now()`-подобных
  зависимостей в счёте.

**Тестовые сюиты расширить, а не ослабить.** Добавь случаи:
`tools/nveco_corrupt_test.py` — профиль без SELF-источника отвергается; цифра
`concentration` без цитаты отвергается; сущность с одной подтверждённой связью не
проходит членство. `tools/nvnet_nosource_test.py` — `disputed` не схлопывается в
`confirmed`; `bilateral` не ставится, когда обе цитаты с одного домена.
`tools/nveco_retire_test.py` — ретирование по членству отличимо от ретирования по
молчанию агента.

# 8. Журнал сборки

`handoff/AI-ECOSYSTEM-V4-BUILD-LOG.md`, по образцу предыдущих. Обязательно:

1. **Числа до/после** по каждому критерию приёмки. Особенно: сколько сущностей потеряли
   статус при пересчёте тиров, и какой стала доля связности NVIDIA.
2. **Всё, что не сошлось.** Если правило членства выбрасывает узел, который очевидно
   должен быть на карте — это находка о правиле, пиши её, не подкручивай порог молча.
3. **Решения, принятые за пользователя,** и почему.
4. **Что осталось незакрытым** и в какой фазе закрывается.
5. Отметь: префиксы `nveco_`/`nvnet_` сохранены намеренно, имя историческое.

Отдельно: `handoff/AI-ECOSYSTEM-NETWORK-CHANGELOG.md` получает новую категорию —
**вход и выход из ядра** (кто поднялся, кто опустился, по какой мере).

# 9. Запуск

```bash
python run_nvidia.py <YYYY-MM>              # v2-половина: ingest, verify, score, cycles
python run_network.py <YYYY-MM> --deliver   # сеть + доставка в дашборд
python tools/nveco_corrupt_test.py && python tools/nvnet_nosource_test.py
```

Оба оркестратора возвращают 1 и **не пишут ничего**, если валидатор контракта не прошёл.

**Дашборд идёт отдельным проходом** и своим промптом. Контракт из §4 — единственная точка
стыковки, он дословно повторяется в обоих. В одностороннем порядке его не меняет никто:
если по ходу выяснится, что форма должна быть другой — остановись и запиши это в журнал
как предложение к контракту, а не как правку.
