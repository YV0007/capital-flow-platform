## Порядок работ

1. **Бриф `agents/eco-dossier.md`.** По образцу `agents/target-profiler.md` (пакетный
   профайлер недельного конвейера — он работает, не изобретай заново). Состав досье — §5
   «Правка 4» спецификации. Обязательные требования брифа:
   - **≥1 источник, изданный самой сущностью.** Компания, описанная только чужой
     отчётностью, не проходит. Если своего издателя у сущности нет (технология,
     юрисдикция) — правило снимается фактом пустого `domains`, а не решением агента.
   - Каждое ребро — с дословной цитатой ≤15 слов, не собранной из кусков, не переведённой.
   - Каждая цифра в прозе и в `concentration` — из цитаты, привязанной к этой сущности.
   - Проза двуязычна `{ru, en}`, обе стороны непусты. Имена не переводятся.
   - Отдельная секция «названо, но на карте нет» → очередь кандидатов.
   - Агент **не** назначает тир источника, `integration`, `core` и `sidedness`.

2. **Пакетчик `tools/make_dossier_batches.py`.** По образцу
   `tools/make_research_batches.py`, включая контекстный пакет: что уже знаем об этой
   сущности (существующий профиль, её рёбра, её источники), что сработало, что отклонили
   в прошлый раз. Пакеты по 8. Ярус берётся из БД по `integration`.

3. **Стадия сверки `engine/nveco_reconcile.py`** между `nveco_ingest` и `nveco_score`.
   Ставит `sidedness`: `bilateral` / `single` / `disputed` по §5 «Правка 4». Спор не
   решает и сторону не удаляет никогда. Обе цитаты едут в `counterEvidence`.

4. **Прогон по ядру.** ~30 досье, пакетами по 8. Полное досье каждому: описание,
   рёбра вверх и вниз, четыре фактора с обоснованиями, `concentration` с цитатой,
   кандидаты.

5. **Вернуть четырёхфакторную рубрику.** У ядра `concentration` теперь заполнен —
   верни веса контракта (0.30/0.30/0.25/0.15). У неисследованных ярусов формула Фазы 0
   остаётся до их очереди; пометь это в payload полем на уровне сущности, чтобы
   потребитель не сравнивал несравнимое.

6. **Слоевые агенты.** Восемь `agents/nveco-*.md` сохраняются, мандат сужается: искать
   сущности, которых на карте ещё нет, в своём слое. Досье описывает известный узел и
   слепо к неназванному — это и есть работа слоевого обхода. `nveco-strategic`
   переориентируй на проход сверки: разбирает `disputed`, ищет межслойные связи, которых
   не заявил ни один конец, новых сущностей не заводит.

## Приёмка

- **0 сущностей ядра, у которых все источники принадлежат NVIDIA** (по карте целиком до
  начала кампании было 41 из 107)
- у каждой сущности ядра `sourcing.selfSourced ≥ 1` — либо пустой `domains` с причиной
- медиана `sourcing.total` по ядру **≥ 4** (по карте до кампании — 1)
- у каждой сущности ядра `concentration` заполнен и обоснован цитатой
- доля `bilateral` среди рёбер ядро↔ядро измерена и записана
- ни одно ребро не потеряно молча: связи, которые досье не подтвердило, уходят через
  штатное ретирование по `owner_agent`, с причиной
- обе тестовые сюиты зелёные, включая новые случаи на `bilateral` / `disputed` /
  отсутствие SELF-источника
- `npm run build` в `ab-investment` проходит на новом payload
