# Часть I. Каким станет продукт

## 1.1 Что видит гость

Незалогиненный посетитель видит **всё то же, что и сегодня** — но по настоящим
адресам. Дашборд не превращается в закрытый клуб.

Отличие: любую страницу можно **отправить ссылкой**, открыть в новой вкладке,
добавить в закладки, вернуться кнопкой «назад». Сегодня не работает ничего из
этого — раздел живёт в `useState`, адрес не меняется никогда.

## 1.2 Карта адресов

Составлена из того, что в коде уже есть. Четыре отчёта — ровно те, что лежат в
`research-library.json`.

| Адрес | Что там |
|---|---|
| `/` | **Лендинг** — что это, для кого, кнопка входа |
| `/dashboard` | Нынешняя главная витрина (чипы, потоки, холдинги, цепочка) |
| `/research` | Библиотека исследований (4 обложки) |
| `/research/capital-flow` | Карта потоков капитала |
| `/research/capital-flow/ecosystem` | Карта экосистемы |
| `/research/capital-flow/funds` | Трекер фондов |
| `/research/capital-flow?flow=…` | Карта с раскрытой сделкой |
| `/research/data-centers` | Дата-центры для ИИ |
| `/research/holdings` | Холдинги, все девять |
| `/research/holdings/:id` | Один холдинг (`kkr`, `softbank`, …) |
| `/research/proxy` | Прокси |
| `/tracker` | Витрина VC-трекера |
| `/tracker/:companyId` | Одна компания в трекере |
| `/login` · `/account` | Вход и личный кабинет |
| `/privacy` · `/terms` | Политика и условия |

Три карты Capital Flow сейчас переключаются внутренним состоянием
(`MapSwitch`) — станут тремя адресами.

**Нынешняя главная уезжает на `/dashboard`.** Она хороша как рабочий экран и
непонятна как первая страница для человека, который видит проект впервые.

## 1.3 Что меняется после входа

Вход — по ссылке на почту (magic link) или через Google. **Паролей нет вообще**,
поэтому и хранить нечего, и утекать нечему.

Появляется то, чего сегодня нет:

- **Вотчлисты переживают браузер.** `cfm:watchlists:v1` сейчас лежит в
  localStorage одного браузера. Инкогнито, другой ноутбук, чистка кэша — списка
  нет. После перехода он в базе, привязан к аккаунту.
- **Язык и тема закреплены за человеком, а не за устройством.**
- **Работа в трекере перестаёт быть одноразовой.** Наблюдения, скоринг,
  синдикатный лог, cap-events, меморандумы — сегодня всё это в localStorage.
  Очистка кэша стирает их без следа.
- **Личный кабинет** `/account`: имя, язык, тема, выход, **экспорт своих данных
  и удаление аккаунта** (требование GDPR, не украшение).
- **Перенос накопленного.** При первом входе — разовое предложение забрать то,
  что уже лежит в этом браузере. По кнопке, не молча.

Гость по-прежнему пользуется всем публичным. Вход ничего не отбирает.

## 1.4 Что мы узнаём о пользователях

Собственная аналитика в вашей же базе, без сторонних трекеров, **после явного
согласия**:

- какие разделы и сущности открывают, сколько на них задерживаются;
- какие сделки, холдинги, секторы разворачивают;
- какими фильтрами и переключателями реально пользуются;
- **кто читает RU, а кто EN** — сегодня неизвестно совсем;
- что ищут внутри карты;
- откуда пришли (referrer), без построения профилей по сети.

Отсюда — «самые просматриваемые сущности недели», понимание, какие секторы
интересны на самом деле, и основа для персональной сводки.

**Персональных данных в событиях нет: ни почт, ни имён, ни IP.** Связь с
человеком — через `user_id`, и только для вошедших, давших согласие.

## 1.5 Что остаётся как есть

Недельный конвейер не трогаем: движок → `capitalMap.json` → сборка → Vercel.
Контракт с движком переход не затрагивает. Ворота i18n (`i18n:check`,
`i18n:lint` в `prebuild`) остаются и продолжают ловить правила 1–6.

## Фаза 0 — Настоящие маршруты

Домен не нужен: работает на `ab-investment.vercel.app`. `vercel.json` уже
переписывает `/(.*) → /index.html`, то есть инфраструктура к прямым ссылкам
готова — трогать её не придётся.

### Что делаю я

1. `react-router-dom`; таблица маршрутов в `src/routes.jsx` по карте из §1.2.
2. Из `App.jsx` (789 строк) уходят `mode`, `activeResearchId`,
   `researchContext`. `updateMode()` и `openResearchPage()` → `navigate()`.
3. `researchContext` (`{ flowId }`) → `?flow=…`: ссылка на конкретную сделку
   начинает работать.
4. Три карты Capital Flow разъезжаются по адресам.
5. `React.lazy` + `Suspense` на маршрут.
6. Сохраняю два приёма, на которых держится устойчивость: `key={lang}`
   (перемонтирование тела при смене языка) и `ErrorBoundary` вокруг **тела**
   раздела, но не шапки. Оба переносятся на маршруты явно.

### Готово, когда

`npm run build` зелёный вместе с воротами i18n; каждый адрес открывается прямой
ссылкой и переживает F5; «назад» работает; оба языка, обе темы живы.

## Фаза 0.5 — Вес страницы

**Этого не было в v1, и это важнее, чем кажется.** Замерено сегодня:

| Что | Сейчас | Почему больно |
|---|---|---|
| Один JS-чанк | **12 МБ сырых / 2,97 МБ gzip** | Посетитель на телефоне тянет 3 МБ, чтобы увидеть заголовок |
| Tailwind | **`cdn.tailwindcss.com`, скриптом в `<head>`** | Это инструмент для прототипов, не для продакшена. Компилирует CSS в браузере на каждый заход |
| `#root` | `opacity: 0` до `tw-ready` | Страница **намеренно пустая**, пока CDN не отработает. Так и было задумано — но поисковик и человек на медленной сети видят белый экран |
| JSON в бандле | **90 импортов, 13 МБ** в `src/data` | `aiEcosystemNetwork.json` 2,2 МБ, `dc-details.json` 1,9 МБ, `capitalMap.json` 1,1 МБ — всё компилируется в JS-модули |

Пока это так, лендинг из фазы 5 бессмысленен: он не проиндексируется и не
загрузится. Поэтому фаза 0.5 идёт **до** домена, а не после.

### Что делаю я

1. **Tailwind становится сборочной зависимостью.** `tailwindcss` + `postcss` в
   devDependencies, конфиг, один CSS-файл на входе. CDN-скрипт и хак `tw-ready`
   с `opacity: 0` уходят вместе. Классы в разметке не меняются.
2. **Данные выходят из бандла.** Крупные JSON переезжают в `public/data/` и
   грузятся `fetch`-ем на своём маршруте, а не `import`-ом при старте. Порядок
   — по весу: `aiEcosystemNetwork`, `dc-details` (+`.en`), `capitalMap`,
   `nvidiaEcosystem`, `fundTracker`. Мелкие (`research-library.json` — 8 КБ,
   `options.json`) остаются импортами: дробить их незачем.
3. Скелеты загрузки на местах, где раньше данные были синхронно доступны.
4. Замер до/после в отчёте.

**Риск, который я держу в голове:** `capitalMap.js` отдаёт `bi()`-геттеры поверх
`capitalMap.json`. Асинхронная загрузка не должна превратить геттер в
`undefined` на первом кадре — таксономия резолвится после прихода данных, а не
до. Это ровно тот класс ошибок, ради которого существуют ворота i18n.

### Готово, когда

Первый чанк — **сотни килобайт, не мегабайты**; сеть при заходе на `/` не тянет
карту потоков; Tailwind собран, `tw-ready` удалён, белого экрана нет; оба языка,
обе темы; ворота зелёные.

## Фаза 1 — Домен

**Здесь нужны вы: я не совершаю покупки и не регистрирую аккаунты.**

### Что делаете вы

**2. Подключить к Vercel.** Project → Settings → Domains → Add. Вносите **те

**3. Сказать мне домен.**

### Что делаю я

Канонический адрес (редирект `www` → корень или наоборот), обновление внутренних
ссылок, проверка всех маршрутов на новом домене.

## Фаза 2 — Supabase и вход

**Supabase** — Postgres, аутентификация и построчная защита (RLS) в одном месте.
Аналитика из §1.4 — SQL-задача; RLS не даёт браузеру дотянуться до чужих строк;
свой сервер не нужен, статическая сборка на Vercel не меняется.

Рассматривались: **Clerk + Neon** — вход приятнее, но два поставщика и платно
раньше; **Firebase** — NoSQL, и первый же вопрос «какие секторы смотрят чаще»
упирается в отсутствие джойнов.

### Что делаете вы

**1. Создать проект Supabase.**

**Регион — обязательно европейский** (Frankfurt / Ireland). У вас ожидаются
пользователи из ЕС, значит персональные данные должны лежать в ЕС. Смена региона
потом = перенос базы вручную.

**2. Прислать мне два значения** (Project Settings → API):
- **Project URL**
- **anon / public key**

Anon-ключ публичен по устройству — он попадает в бандл, это нормально: защищает
не он, а RLS. **`service_role` ключ не присылайте и никуда не вставляйте** — он
обходит RLS целиком.

**3. Настроить почту.** Встроенный отправитель Supabase ограничен единицами
писем в час и шлёт со своего домена — хватит нам с вами на проверку, не хватит
живым людям.

Заведите Resend или Postmark, добавьте домен, внесите выданные DKIM/SPF в DNS,
дождитесь верификации. Затем Supabase → Authentication → SMTP Settings.

Без этого ссылки для входа уходят в спам — самый частый способ тихо провалить
запуск регистрации.

**4. Google-вход — по желанию.** Google Cloud Console → новый проект → OAuth
consent screen (External) → Credentials → OAuth client ID → Web application.
В Authorized redirect URIs — адрес, который покажет Supabase (вида
`https://<ref>.supabase.co/auth/v1/callback`). Client ID и secret — в Supabase →
Providers → Google. Magic link работает и без этого.

**5. Переменные в Vercel:** `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` — для
Production и Preview, затем передеплой.

### Что делаю я

`@supabase/supabase-js`; клиент в `src/lib/supabase.js`; `AuthProvider` рядом с
`LangProvider`; страницы `/login` и `/account`; состояние входа в шапке; защита
только для `/account` — остальное публично.

### Готово, когда

Вход по ссылке из почты и через Google работает на живом домене; сессия
переживает перезагрузку; выход чистит всё; аноним по-прежнему видит весь сайт.

## Фаза 3 — Данные привязываются к аккаунту

Это и есть исходный запрос: «настройки закреплены за аккаунтом».

**Почему это дёшево.** Вся запись идёт через `src/lib/storage.js` — **две
асинхронные функции**, `loadKey` и `saveKey`. Все ~30 вызовов в `App.jsx`
написаны через `await`. Меняется один файл; трекер не переписывается.

Единственное исключение — вотчлисты: `useWatchlists.js` дёргает `localStorage`
напрямую, синхронно. Его перевожу на тот же `storage.js`.

### Что делаю я

**Схема** (`supabase/migrations/0001_init.sql`, в репозитории, не накликанная):

```
profiles    id → auth.users · display_name · locale · theme · plan · created_at
user_prefs  user_id · key · value jsonb · updated_at
user_data   user_id · scope · key · value jsonb · updated_at
```

`user_data` ложится 1:1 на нынешние ключи трекера `${prefix}:${suffix}`.
`plan` лежит пустым — чтобы платные тарифы, если появятся, не потребовали
миграции живых данных.

RLS `user_id = auth.uid()` на каждой таблице, без исключений.

Дальше: переписываю `storage.js` с той же сигнатурой; `app:lang`, `app:theme` и
`cfm:watchlists:v1` переезжают для вошедших; localStorage остаётся write-through
кэшем, чтобы интерфейс не ждал сеть; экран разового переноса при первом входе.

**Серверные данные не перезаписываются молча** — только по кнопке.

### Готово, когда

Вотчлист, собранный на ноутбуке, открывается на телефоне; наблюдение из трекера
переживает смену устройства; язык и тема едут с аккаунтом; аноним работает как
раньше; чистка localStorage у вошедшего ничего не теряет.

## Фаза 4 — Согласие и аналитика

**Порядок именно такой: сначала согласие, потом сбор.** У вас ожидаются
пользователи из ЕС — значит поведенческая аналитика без предварительного
согласия незаконна. До нажатия «принять» не собираем ничего сверх необходимого
для работы сайта.

### Что делаете вы

**Утверждаете тексты** политики и условий и **срок хранения событий** (разумно
— 12 или 24 месяца). Черновики пишу я; содержание и срок — ваше решение.

Я не юрист, и это не юридическая консультация. Если проект станет заметным,
черновик стоит показать юристу — но для запуска связки «политика + баннер +
удаление аккаунта» этого достаточно, и она несравнимо лучше, чем ничего.

### Что делаю я

`supabase/migrations/0002_events.sql`:

```
events  id · user_id (nullable — аноним) · session_id · ts
        name · props jsonb · path · referrer
```

Плюс:
- `src/lib/analytics.js` с `track(name, props)`, автоотправка на смену маршрута,
  **всё под флагом согласия**;
- баннер согласия: «принять» и «отклонить» равнозначны, отказ запоминается;
- `/privacy`, `/terms`;
- **экспорт своих данных** и **удаление аккаунта с каскадом** в `/account` —
  статьи 15 и 17 GDPR, без них комплаенса нет;
- задание, стирающее события старше согласованного срока;
- представления-свёртки, чтобы отчёты не сканировали таблицу целиком.

Персональных данных в `props` нет.

## Фаза 5 — Лендинг и SEO

Индексация нужна публичным страницам, не дашборду.

### Что делаю я

1. **Лендинг на `/`**: что это, для кого, что внутри, живой скриншот или
   фрагмент карты, кнопка входа. Нынешняя главная уезжает на `/dashboard`.
   Копию пишу — вы правите.
2. Мета- и OG-теги на маршрут, `sitemap.xml`, `robots.txt`.
3. Пререндер публичных страниц на сборке (`vite-plugin-ssg` или аналог) — чтобы
   в HTML был текст, а не пустой `<div id="root">`.

### Почему **не** Next.js

Причина в коде, не во вкусах. Языковой слой резолвит подписи через геттеры
`bi()`, вычисляемые при импорте модуля (правила i18n 1–6 в `CLAUDE.md`
существуют ровно поэтому). SSR исполняет модули на сервере, где у `getLang()`
нет контекста запроса — каждая подпись таксономии становится источником ошибки
на каждый запрос. Плюс `react-force-graph-2d` и канвасы работают только в
браузере, а компонентов 114.

Переписывали бы самый хрупкий слой ради SEO на нескольких страницах. Пререндер
даёт то же самое и не трогает i18n.

# Часть VI. Риски

| Риск | Как закрываем |
|---|---|
| Потеря данных трекера при переносе | Перенос по кнопке; localStorage не чистится; серверное молча не перезаписывается |
| Асинхронные данные ломают `bi()`-геттеры | Фаза 0.5 идёт отдельно и целиком, с прогоном ворот i18n; таксономия резолвится после прихода данных |
| `service_role` ключ в бандле | В клиент попадает только anon; RLS на каждой таблице |
| Ворота i18n падают после правок | `npm run build` на каждой фазе; ворота уже в `prebuild` |
| Чёрный экран из-за `ErrorBoundary`/`key={lang}` | Оба приёма переносятся на маршруты явно и проверяются |
| Письма входа в спаме | Свой SMTP на своём домене с DKIM/SPF — фаза 2, не «потом» |
| Сбор данных без согласия | Аналитика физически не стартует до флага согласия |
| Регион БД вне ЕС | Выбирается один раз в фазе 2; вынесено в чеклист отдельным пунктом |
