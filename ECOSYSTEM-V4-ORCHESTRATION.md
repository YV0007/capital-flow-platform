# Кампания v4 — регламент оркестровки

Кто что запускает, что проверяется между сессиями, где кампания имеет право
остановиться. Ведёт оркестратор (сессия в `ab-investment`), исполняют сессии движка.

## Документы

| файл | что это |
|---|---|
| `ECOSYSTEM-V4-SPEC.md` | **канон.** Диагноз, контракт `/4`, четыре правки, инварианты. Читают все сессии целиком |
| `ECOSYSTEM-V4-A-ENGINE-DEANCHOR.md` | сессия A — Фаза 0, механическая, без сети |
| `ECOSYSTEM-V4-B-ENGINE-DOSSIERS.md` | сессия B — Фаза 1, машинерия досье + ядро |
| `ECOSYSTEM-V4-C-ENGINE-ROTATION.md` | сессия C — Фазы 2–3, ротация, членство, регламент |
| `ECOSYSTEM-V4-D-DASHBOARD.md` | сессия D — дашборд. **Пишется после A**, по факту уехавшего payload |

Определения живут только в каноне. Промпты сессий их не дублируют.

## Порядок и зависимости

```
A (движок, без сети)
├──> B (движок, исследование ядра) ──> C (движок, ротация и членство)
└──> D (дашборд)                        [D и B идут параллельно]
```

`D` пишется после `A`, потому что контракт может измениться по ходу: строим против того,
что реально уехало, а не против ожидания.

## Что делает оркестратор между сессиями

Не «принимает работу» у пользователя — проверяет сам и идёт дальше.

**После A:**
1. Читает раздел Фазы 0 в `handoff/AI-ECOSYSTEM-V4-BUILD-LOG.md`.
2. Прогоняет приёмку заново своими руками, не доверяя отчёту: grep на якорь, состав
   полей payload, обе тестовые сюиты, `npm run build` на дашборде.
3. Сверяет **фактический** `schema`/`version` и форму payload с §4 канона. Если движок
   правил контракт — переносит правку в канон и в промпт D. Это штатный ход, а не сбой.
4. Фиксирует контрольные числа кампании. **Фаза 0 их уточнила:** долг кампании — не
   41 (сущности с одним издателем — NVIDIA), а **75 из 107** — сущности без единой
   СОБСТВЕННОЙ цитаты. И медиана источников равна не «примерно одному», а РОВНО одному
   у всех 107. Разрыв integration между первым и вторым местом — семикратный (100 / 30).
   Дальше всё меряется от этих чисел.
5. Запускает B и D.

**После B:** проверяет, что ядро действительно исследовано — `selfSourced ≥ 1` у всех,
медиана источников по ядру ≥ 4, `concentration` заполнен, доля `bilateral` посчитана.
Читает раздел «профиль до и после»: если он не показывает разницы, кампания не сделала
того, ради чего затевалась, и это фиксируется как результат, а не заглаживается.

**После C:** финальная сверка контрольных чисел, проверка `ops_check`, чтение честного
раздела «чего архитектура всё ещё не видит».

**После D:** сборка и деплой дашборда, обновление памяти проекта.

## Где кампания имеет право остановиться

Только здесь. Всё остальное решается на месте и пишется в журнал.

1. **Валидатор контракта не проходит.** Оркестратор не пишет payload руками и не
   ослабляет валидатор. Разбирается причина.
2. **Правка задевает недельный конвейер или Fund Tracker.** `sources.yaml` и `capital.db`
   общие. Ломать соседей нельзя даже ради правильной архитектуры.
3. **Приёмка фазы не сходится дважды подряд.** Один заход на починку — нормально; второй
   означает, что неверна постановка, а не исполнение, и это идёт к пользователю с
   конкретным вопросом.

## Что пользователь видит

Ничего, пока кампания идёт, кроме того, что сам захочет посмотреть. По завершении —
один отчёт: контрольные числа до и после, что изменилось на карте, что осталось
незакрытым.

## Долг, накопленный для сессии D (дашборд)

Собирается по ходу кампании оркестратором, чтобы не искать заново при написании промпта D.

| откуда | что |
|---|---|
| Фаза 0 | колонка «Рычаг» в `EcoTable.jsx` пуста — поля `strategicControl` больше нет. Заменить на `concentration` (заполняет Фаза 1) |
| Фаза 0 | `nvidiaEcosystem.js` держит `strategicControl` в списке факторов — таксономия реэкспортируется в v3-адаптер, править там |
| Фаза 0 | `integration` не отображается нигде. Это ОСНОВНОЙ ранг карты по контракту /4 — нужен и в таблице, и в панели, и как порядок сортировки по умолчанию |
| Фаза 0 | `sidedness` (`bilateral` / `single` / `disputed`) не отображается. `bilateral` — новый максимум доказательности, он должен быть виден в карточке связи |
| Фаза 0 | `sourcing` (`total` / `selfSourced` / `byTier`) не отображается. Это честность профиля — сколько источников и сколько своих |
| Фаза 0 | долг перевода в дашборде — 15 голых русских строк (был 38, Фаза 0 вернула к прежним 15) |
| Фаза 3 | флаг `pendingDossier` — узел показан, помечен, не ретирован. Нужна визуальная пометка, иначе непокрытый узел читается как исследованный |
| канон | `pivotal` помечен deprecated, живёт один выпуск. D переводит компоненты на `core` |
