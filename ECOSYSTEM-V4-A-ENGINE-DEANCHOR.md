## Порядок работ

1. **Реестр доменов.** Создай `config/entity_domains.yaml`: `id → {domains: [], cik}`.
   Заполни для всех 107 сущностей, у кого есть свой издатель. Источник данных — уже
   собранные `sources[].url`, поле `domain` в payload (заполнено у 14), `ticker` (у 64),
   `config/external_ids.yaml`. Домены, которые не выводятся из имеющихся данных, ставь
   только если уверен; сомнительное оставляй пустым и перечисли в журнале — Фаза 1
   заполнит их из досье. У технологий (`cuda`, `nvlink`) и юрисдикций (`taiwan`) издатель
   — владелец/правительство; если своего издателя нет, поле пустое, и правило
   `min_self_sources` для такой сущности снимается этим фактом, а не исключением в коде.

2. **Функция тира.** `nveco.domain_tier(url)` → `nveco.source_tier(url, subject_id,
   counterparty_id=None)` по лестнице из §5 «Правка 2» спецификации. Из
   `config/sources.yaml` удали все строки, зашитые под NVIDIA — они становятся обычными
   данными узла `nvidia`. Блок `nveco_tiers` перепиши в безъякорных формулировках.
   **Блок `tier1..tier5` недельного конвейера не трогай.**

3. **Пересчёт тиров и статусов** по всем существующим источникам. Часть статусов упадёт:
   «тир 1, потому что nvidia.com» станет тиром 2 везде, где предмет — не NVIDIA. Это
   правильный результат. Зафиксируй дельту числом.

4. **Рубрика.** `strategicControl` → `concentration` (шкала в спецификации). У уже
   собранных сущностей значения `strategicControl` **не конвертируются механически** —
   они измеряли другое. Проставь `concentration = null` и обоснование «ожидает досье»,
   а `criticality` считай по трём факторам с пронормированными весами
   (0.353/0.353/0.294), записав это в журнал как временную меру Фазы 0. Фаза 1 заполняет
   `concentration` из досье и возвращает четырёхфакторную формулу.

5. **`integration`.** Собери из уже считающихся `gravity` + `centrality` по формуле из
   спецификации. Веса — в `config/nvnet_edges.yaml`, не в коде. `gravity` оставь как есть.

6. **Членство.** `config/nveco_anchors.yaml` удали. Создай `config/nveco_scope.yaml`.
   Правило двух шагов и поле `hops` вырежи из `nveco_ingest` и payload. **Проверки
   членства пока НЕ включай** — только пропиши и посчитай, кто бы их не прошёл, в отчёт.
   Включает их Фаза 3.

7. **Ядро.** `core = топ-30 по integration.score`, ставится в `nvnet_centrality`.
   `pivotal` эмитится зеркалом `core` весь выпуск v4.0. `config/nvnet_pivots.yaml`
   перестаёт задавать состав — оставь в нём только `release` и веса, список пивотов
   удали, сославшись в комментарии на правило.

8. **Тесты.** Расширь обе сюиты случаями из §7 спецификации. Ослаблять существующие
   нельзя.

## Приёмка — проверяется скриптом, не глазами

- `grep -riE "anchor|якор" engine/ config/ run_*.py | grep -v archive/` → пусто
- в payload нет `hops`, нет `ecosystem: "nvidia"`, нет `strategicControl`
- у каждой сущности есть `integration.score`, `sourcing`, `core`
- `pivotal` присутствует и равен `core` у всех 107
- `nveco_corrupt_test` и `nvnet_nosource_test` зелёные, включая новые случаи
- `run_nvidia.py <месяц> --offline` и `run_network.py <месяц>` проходят от нуля
- **дашборд продолжает собираться и рендериться без правок** — проверь копией payload в
  `ab-investment/src/data/aiEcosystemNetwork.json` и `npm run build` в том репозитории;
  если падает, чини payload, а не дашборд, и запиши, что именно упёрлось
